# Dawg Viewer 0.4.0

Dawg Viewer 0.4.0 adds a vehicle simulator that works from the Car tab, ways to bring tracks in, map backgrounds, and labels that say where every number comes from.

## Highlights

### Vehicle simulator

- Added a Sim tab that works out 75 m acceleration, skidpad time, lap time and top speed for the car on the Car tab and sets them against the open log.
- Added Engine & gearing, Acceleration, Lap, Skidpad & balance, Dampers and Sweeps pages.
- Added best shift points, a torque curve estimated from full-throttle pulls in a log, and the overall gearing on the Car tab.
- Added Magic Formula tires, with import of `.tir` files and MATLAB tire models, and tire pressure as a value to sweep.
- Added dyno file import for the torque curve and shock dyno import for the Dampers page.
- Added a what-if car for comparing a changed value without saving it.
- Added simulated channels for the laps of a log, and the option to open any simulated lap in the Viewer as a log of its own.

### Tracks

- Added track import: OptimumLap `.OLTra` files, tables of sections, and outlines as x/y points, latitude and longitude, GPX, KML or GeoJSON.
- Added saved tracks, kept as files in the config folder.
- Added lookup of race track outlines in OpenStreetMap, around the open log or by name.
- Added an ideal line through a track or beside a driven lap, with a theoretical and a likely lap time.

### Maps

- Added map backgrounds under the track maps: aerial imagery of the USA and a street map, downloaded when chosen and kept for use offline.

### Data origin

- Channels and car values now say whether they are measured, filtered, calculated or theoretical.
- Added cleaned `Lat G`, `Long G` and `Vert G` channels and a `GPS Speed` channel for logs without a speed channel, each with the direction its axis points.
- The Aero panel can use the filtered or the raw accelerometer data.
- The Sim tab warns on every page while it is running on the stand-in engine curve.

### First start

- The app now opens a sample log the first time it runs, so there is something to see: `Run-1 sample.csv`, real data measured on the G26, labelled as the sample while it is open.
- The app comes with G26 car values (team spec sheet, 8/8/26 dyno run, team tire model, a few assumptions). They are used wherever the device profile has no value of its own and are tagged "G26 stock" on the Car and Sim tabs.
- The Dampers page comes with the team's shock dyno table (`G27_shock_dyno_data.xlsx`, G25 and G26 right-front shocks), labelled as coming with the app. Importing a shock dyno file replaces it.

### Setups

- The setup in use is now saved into its file as you work; its name and "saved" show next to the Setups button.
- A new setup starts from the original view, the one the app comes with, unless "What's open now" is picked.
- Setups now also hold the Sim, damper and split settings.
- The view, the setup in use and the last log are kept in the config folder (`session.json`) instead of only in the app's browser storage, so they follow the config folder and survive a reinstall.

### Viewer

- A plot can be made taller or shorter by dragging its bottom edge; double-click the edge to reset it.

### Car tab

- Added the simulator's inputs: torque curve, tire model, suspension, shift time and drivetrain efficiency.
- Added import of car values from another device file.

## Upgrade notes

Existing settings, device profiles, setups and logs keep working. The first time 0.4.0 runs it copies the sheets, start/finish line and other view settings from the app's browser storage into `session.json` in the config folder. On Windows, run the new installer over the installed version rather than uninstalling first: the uninstaller removes that browser storage, and with it the view, before 0.4.0 can copy it. Once 0.4.0 has run, uninstalling no longer loses the view.

Car values that are missing from a device profile used to fall back to typical FSAE numbers and now fall back to the G26 stock values where there is one (mass 277 kg instead of 290, final drive 3.27 instead of 3.08, tire radius 0.200 m instead of 0.229, redline 13,000 instead of 13,500, and others). Launch and Aero results that relied on a typical value change with them. Values already in a profile are untouched.

The app writes `Run-1 sample.csv` (about 11 MB) into the logs folder once. It can be deleted.

Setups are now saved as you work. Using a setup and then changing a plot changes that setup's file; to try something without touching it, make a new setup from "What's open now" first. The Save button in the Setups window is replaced by New setup, which will not write over a setup that already has the name.

Going back to an older version is not automatic. A device profile saved from the 0.4.0 Car tab, or a `settings.yaml` using `map_sources` or `track_search`, contains keys that 0.3.1 and earlier refuse to load. Keep a copy of the config folder before upgrading if you may need to go back.

The app uses the internet in two new cases, both only when asked: it downloads map imagery when a map background is chosen, and it asks OpenStreetMap servers for a track outline when a search button is pressed. Searching for a track by name stays off until a geocoder is set in `settings.yaml`; read [Track search](../configuration.md#track-search) before turning it on. The config folder gains `maps/`, `tracks/` and `track-search/` folders and a `session.json` file.

For setup, usage, architecture, and contribution details, see the [technical documentation](../README.md).
